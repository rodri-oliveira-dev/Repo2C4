# End-to-end offline example

This example exercises the complete Phase 2 boundary without AI credentials or distributed infrastructure.

The input repository is `examples/fixtures/library-only`. It contains only a .NET library. That absence matters: Repo2C4 must not invent a runtime container.

Assuming the CLI has been built:

```bash
CLI="dotnet src/Repo2C4.Cli/bin/Release/net10.0/Repo2C4.Cli.dll"
mkdir -p artifacts/e2e

$CLI inspect \
  --repository examples/fixtures/library-only \
  --output artifacts/e2e/snapshot.v1.json

cmp examples/end-to-end/snapshot.v1.json artifacts/e2e/snapshot.v1.json
```

The checked-in `snapshot.v1.json` is the deterministic output of that fixture. A human review step then produces the checked-in `architecture.c1.v1.json` and `architecture.c2.v1.json`. The CLI intentionally does not create those architecture decisions automatically.

Generate and validate C1:

```bash
$CLI generate \
  --model examples/end-to-end/architecture.c1.v1.json \
  --output artifacts/e2e/c1

$CLI validate --output artifacts/e2e/c1
```

Generate and validate C2:

```bash
$CLI generate \
  --model examples/end-to-end/architecture.c2.v1.json \
  --output artifacts/e2e/c2

$CLI validate --output artifacts/e2e/c2
```

Each `generate` call also writes `evidence-report.md` beside the LikeC4 files so the reviewed assertions can be traced back to evidence IDs and repository-relative locations. Review the hypotheses section before publication. The expected LikeC4 files are checked in under `generated/c1` and `generated/c2`. CI compares generated bytes against them and runs the official LikeC4 validator.

The C2 output deliberately contains only the focal software-system proposal. There is no executable/host evidence, so no container or runtime relation is fabricated.


## Selective C3 example

The multi-project checked-in model at `examples/models/acme.c2.v1.json` contains more than one C2 container. C3 is generated only when one container is selected explicitly:

```bash
$CLI generate \
  --model examples/models/acme.c2.v1.json \
  --output artifacts/e2e/acme-web-c3 \
  --c3-container el_web

$CLI validate --output artifacts/e2e/acme-web-c3
```

This nests the C3 component proposals for `el_web` in `model.c4` and adds `c3.views.c4`. No C3 view is created for `el_worker` or other containers. The generated components remain review-required because static repository evidence does not independently prove component boundaries or runtime calls.
